# 성능

레퍼런스 환경(RTX 3080 Ti 12GB ×2, [아키텍처 참조](architecture.md#레퍼런스-운영-환경))에서 단독 실행 기준 실측.

## 쪽당 처리 시간

| 문서 유형 | 쪽당 |
|---|---|
| 일반 텍스트 문서 | **~2초** |
| 슬라이드·그림 포함 | **~3.5–4초** |
| 밀집 표·인보이스 | **~3–4초** |
| 고해상도 전폭 대형 표 | **~10초+** |

- 다페이지 총 시간 ≈ 쪽수 × 쪽당 시간 (페이지 순차 처리)
- 재기동 직후 첫 요청은 파이프라인 초기화로 **+30초 내외** (1회성)
- 폭주/도장 재추출 발생 시 해당 페이지당 +2~30초

## CUDA Graph vs eager

vLLM decode 단계를 CUDA Graph(사전 녹화된 커널 시퀀스 재생)로 실행하면 CPU 커널 제출 오버헤드가 사라진다.

| 측정 | eager | **CUDA Graph** | 개선 |
|---|---|---|---|
| 동일 문서 A/B (16쪽 슬라이드) | 5.26s/쪽 | **3.76s/쪽** | **−29%** |
| 단일 문서 이미지 | ~3.3s | **1.7–2.3s** | ~−40% |
| 2쪽 PDF (일반+고해상 표) | 38.1s | **15.3s** | ~−60% |

- 기본값 = CUDA Graph (`ENFORCE_EAGER=0`), decode-only 캡처(배치 1/2/4/8)
- **주의**: 동시 영역 수가 캡처 배치를 넘으면(9–10) eager 폴백 → 영역이 많은 밀집 페이지는 이득 축소. 필요 시 `VL_MAX_CONCURRENCY=8`
- 결과 텍스트는 두 모드 동일 (greedy·결정론적)

## 튜닝 레버

| 레버 | 효과 | 트레이드오프 |
|---|---|---|
| `MAX_PIXELS` 1310720 → 786432 | 고해상도 대형 표 ~20% 가속 | 아주 작은 글자 품질 소폭 저하 |
| `VL_MAX_CONCURRENCY` 9 → 8 | 밀집 페이지도 CUDA Graph 경로 유지 | 동시성 1 감소 (실측 영향 미미) |
| `GPU_MEM_UTIL` 상향 | KV 캐시↑ → 동시성 여유 | 타 프로세스 VRAM 여유 감소 |
| 레이아웃 GPU 분리 (`LAYOUT_DEVICE=gpu:1`) | vLLM과 간섭 제거 | GPU 2장 필요 |

!!! note "동시 업로드와 체감 시간"
    추출은 1건씩 직렬 처리된다. 여러 문서를 동시에 올리면 **대기시간이 합산**되어 느려 보인다 — 실제 처리시간은 응답의 `elapsed_sec` 로 판단할 것. 벤치마크/재현성 측정은 반드시 1건씩.
